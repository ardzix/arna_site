# Arnatech-only domain proof operator pilot (DRAFT, no production changes)
This supersedes prior unmounted ownership-HTTP experiments. No new public write route, SSO token trust, BFF mutation or tenant-facing activation button is shipped. The public website context changes eligibility only for the canonical Arnatech apex; other tenants retain their existing behavior. The migration adds an audit table only; it does not modify unrelated domain rows/statuses. Live authorization of the trusted operator and provider configuration is separate from this code.

## Release gates
- Existing ArnaSite tenant85/public UUID and its organization are pinned with domain ID174 and canonical host. A wrong ID, moved domain, unexpected owner, wrong role, inactive tenant or same-org different CRM destination cannot become eligible.
- Keep both `DOMAIN_VERCEL_PROOF_ENABLED` and `DOMAIN_VERCEL_CHAT_ROUTING_ENABLED` off initially. Test current DNS/Vercel domain evidence, exact artifact/deployed runtime and existing unrelated routing with current Jenkins release.
- Requires independently authorized, audited ArnaSite production operator and dedicated organization/project-scoped Vercel read credential. The complete managed runtime secret must contain exact approved binding, separate receipt key, and immutable operator UUID `DOMAIN_VERCEL_PROOF_OPERATOR_ID` identifying the authenticated execution principal. Do not set operator identity from inline shell arguments, application JWT claims or caller-provided JSON. If a trusted identity/audit mapping cannot be established, stop. The command is not a self-service substitute for fresh owner authorization.
- `verify_arnatech_chat_domain` defaults to a read-only check. Authorized dry run may add `--write-receipt PRIVATE_FILE` under an operator-controlled directory, creating mode0600 without overwrite or symlinks. Receipt is never printed or included in Jenkins logs. Only the explicit authenticated operator apply with `--apply-receipt PRIVATE_FILE` can persist; file is local/private, receipt valid120s, bound to actor, domain challenge, exact tenant/project/team and official read-only Vercel evidence. Recheck state and provider evidence, lock tenant then domain, recheck receipt freshness and commit audit+status together. Remove the private receipt locally after use. Never use SQL or generic domain status mutation.
- Once the write is verified, remove short-lived provider credential/proof gate from runtime if no longer needed, keep audit and enable only the pilot's separate `DOMAIN_VERCEL_CHAT_ROUTING_ENABLED=true` when ready for controlled acceptance. Probe resolver identity and CRM eligibility first; website #2 remains separately off until explicitly approved and safe to exercise. Probe must not generate fake messages/OTP on opening; verify an owner-approved test conversation in the exact inbox before general availability.
- Soft rollback: turn off the website chat flags and pilot-only ArnaSite chat routing. Keep the forward migration and immutable audit; unrelated CMS, domains and conversation history remain intact. An already cached CRM context can survive for its configured bounded TTL (max30s); the website relay checks fresh resolver admission. Recheck live after TTL. Never reverse/drop the audit schema in production as a normal rollback.

No API secret, real JWT, real Vercel verification, database operation or runtime flag change was made while authoring this draft. Tests use synthetic provider calls and disposable PostgreSQL only.
